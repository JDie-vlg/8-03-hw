### Задание 1

**1.1** Необходимо учитывать RPO и RTO, сколько компания готова потерять данных и время восстановления. Подойдет полный бэкап + дифферинциальный бэкап. Например, полный бэкап создается каждый день в 03:00 (это база для восстановления), дифферинциальный бэкап создается каждые 3 часа, сохраняя все изменения накопившиеся с момента последнего полного бэкапа. Если система сломалась в пятницу в 07:00, то необходимо будет накатить полный бэкап с 03:00, а поверх него дифференцированный бэкап. \
**1.2** В данном случае можно использовать горячее резервное копирование. Применяем полный бэкап, а далее все журналы с момента бэкапа до момента сбоя, чтобы накатились все изменения и привести БД в согласованное состояние.

### Задание 2

**Резервное копирование**: `pg_dump --dbname=<имя_бд> --file=<путь_к_файлу_дампа> --format=c --username=<пользователь> --host=<хост> --port=<порт>` \
**Восстановление данных**: `pg_restore --dbname=<имя_бд> --username=<пользователь> --host=<хост> --port=<порт> <путь_к_файлу_дампа>` 

### Задание 3

Инкрементное резервное копирование с помощью бинарных логов: \
Необходимо включить бинарное логирование в конфигурационном файле 
```
[mysqld]
log-bin = /var/log/mysql/mysql-bin.log
server-id = 1  # Обязательно для включения бинарного логирования
expire_logs_days = 7 # Автоматическое удаление старых логов (опционально)
``` 

Выполняется ротация лога
```
sql
FLUSH LOGS;
```
Закрывается текущий бинарный лог и открывается новый.

`cp /var/log/mysql/mysql-bin.01 /backup/binlogs/` 

например, скопируем бинарный лог

для восстановления состояния базы данных на конкретный момент времени используется утилита mysqlbinlog

`mysql -u root -p < /backup/full_dump.sql`
`mysqlbinlog /backup/binlogs/mysql-bin.01 /backup/binlogs/mysql-bin.02 ... | mysql -u root -p`
`mysqlbinlog --stop-datetime="2026-03-14 12:59:59" /backup/binlogs/mysql-bin.01 | mysql -u root -p`
